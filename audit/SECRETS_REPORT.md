# Secrets Report

## Результат

Текущие `.env` файлы игнорируются, `.env.example` не должен содержать значений. Однако `backend/data/db.json` отслеживается Git и использовался как runtime storage; его история считается потенциально чувствительной.

Никакие найденные значения в этот отчёт не скопированы.

## Риск

Session token — credential. Даже если конкретные записи истекли, безопасная реакция должна исходить из предположения, что история могла быть клонирована.

## План

1. Немедленно удалить/отозвать все активные sessions.
2. Ротировать OAuth/API keys, если они когда-либо попадали в runtime DB или логи.
3. Сделать безопасную копию только необходимых пользовательских данных вне Git.
4. `git filter-repo` для удаления `backend/data/db.json` из всех refs.
5. Force-push только после согласования с командой; потребовать fresh clone.
6. Добавить `backend/data/db.json` в `.gitignore`; оставить `backend/data/db.example.json` с вымышленными данными.
7. В CI сканировать working tree и историю.

## Инструменты

Проведён ручной `rg`/Git review. gitleaks и trufflehog локально недоступны, поэтому отрицательное утверждение «секретов больше нет» не делается.
